# Benchmark results: bysound v4 vs ggwave

Generated by `scripts/report.py` from the CSV files in this folder. ggwave commit `060aec73dd7123ccac200442f75bdc7369795ffe`. Machine: Apple M4 Pro, 12 logical CPUs, macOS 27.2.1, Apple clang version 21.0.0 (clang-2100.1.1.101).

All numbers are measured in a **simulated** channel (see README for the exact model). SNR is full-band (0–24 kHz): sound-on signal power over noise power. Success = the exact payload came out of the receiver. With 2 transmissions, success = at least one exact decode. The SNR90 columns give the lowest grid SNR from which every higher grid point, the noiseless case included, reached ≥ 90 % success (grid step in each table title); “—” means not even the noiseless case reached 90 %.

## 3. Decode latency and receiver CPU cost (32 B, AWGN plan, 1 transmission)

Latency = time from the first sample of the transmission to the moment the decoder returned the payload (1024-sample chunk granularity, median over the noiseless trials). Real-time factor = audio duration / receiver thread CPU time (receiver init included). It is given twice: as the median over all trials of the configuration (every SNR, so most trials are below the threshold and nothing is decoded) and as the median over the trials that decoded the payload. bysound listens to all channels of its profile at once (7 normal / 4 robust); ggwave listens to all its protocols (library default).

## 11. Inaudible channels (18–19.5 kHz)

ggwave has no built-in protocol above 18 kHz: its audible protocols use ~1.9–6.3 kHz, DT/MT ~1.1–2.6 kHz and “ultrasound” 15.0–19.4 kHz (6 tones × 16 bins = 4.5 kHz). The 6-tone layout does not fit above 18 kHz (it would reach 22.5 kHz), but the 2-tone DT protocols (2 × 16 bins = 1.5 kHz) and the 1-tone MT protocols (16 bins) do. For this section they were **moved to start at FFT bin 384 = 18,000 Hz** with ggwave's public C API (`ggwave_txProtocolSetFreqStart`, `ggwave_rxProtocolSetFreqStart`), a custom configuration, not a ggwave default. Everything else keeps the library defaults. DT's start/end markers are generated from the protocol's own start bin, so they move too. **The ggwave receiver is restricted to the six moved protocols** (`ggwave_rxToggleProtocol`); DT runs in the default variable-length mode, MT in fixed-length mode (the receiver knows the payload length, as in section 7). bysound is unchanged: `top` (18.0–19.5 kHz, 2 tones), with the same receivers as in the other sections (normal: 7 channels, robust: 4). Same channel, chunking, grids and trial counts as sections 1, 4 and 5, **and the same seeds** (one transmission).

Seed check: 8140 bysound trials of this plan have a counterpart in the `snr`, `cond` or `size` plan; 8140 give the same result (success, decodes, wrong payloads, latency), 0 differ.
